# Scope PDF export and landing polish

### Features

- **Scope PDF export** for organisation leads: from a context actions menu, collect published PDFs for the owner scope (company includes departments and teams; department includes its teams) into an async zip. Progress and download via toast and the notifications inbox, labeled by scope (`Company` / `Departments · …` / `Teams · …`). Older exports rotate after a short per-user retention window.
- **Destinations under Admin:** shared remote targets for operational backups live on their own nav entry (no longer buried only in backup settings).
- **Landing:** German and English UI with English URL path segments; navbar language switcher.
- **Landing:** light / dark / auto color scheme toggle; showroom screenshots follow language and theme.

### Fixes

- Freshness hub: scan and decision actions stay disabled in demo mode, with a clear tooltip instead of failing quietly.

## For operators

- Database migration adds `ScopePdfExportRun` (and related status enum). Apply migrations before relying on scope PDF export.
- Worker image must include the `zip` CLI; scope PDF export fails with a clear error if it is missing.
- Scope PDF zips are offline mirrors for humans – not DR backups and not restorable into DocsOps (see runbook Backup/Restore).
- Operational backup destinations UI moved to **Destinations** under Admin; backup default destination labeling is unchanged in behavior.
